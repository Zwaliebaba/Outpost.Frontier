# Risks

Ordered by how much of the plan each one can sink or stretch.

| # | Risk | Likelihood / impact | Mitigation | Watch |
|---|---|---|---|---|
| R1 | **Bit-exactness takes far longer than the port itself**: hidden dependencies on Mono behaviour (collection order, sort ties, string hashes, overflow), a float that reaches simulation state, uninitialised-state differences | high / high | the hazards measured and ported once in `Core` ([Architecture.md §4](Architecture.md)); per-component checksums and the first-divergence report; state-frame diffs from the Recorder; test vectors computed in the original runtime | divergences found per week in phase 3 |
| R2 | **Mission scripts don't recover cleanly** from uScript's generated C# (1.24M lines, 82 graph components) | medium / high | recovery is mechanical (the generated code is regular) and its node-type report says early how complete it is (Plan 2.6). Fallback per graph that fails: translate the generated C# to C++ mechanically against a small uScript runtime | share of graphs recovered after 2.6 |
| R3 | **Lighting cannot match**: the WorldArt scenes use Unity 5 real-time GI (Enlighten), whose data is not portable, and only one baked lightmap exists | certain / medium | an offline bake of our own (light probes and lightmaps per WorldArt scene) from the scene's lights and geometry, tuned against reference shots; looser comparison thresholds for indirect light | SSIM on WorldArt reference shots |
| R4 | **The shader rewrite is large and needs judgement**: 217 shaders, compiled only (D3D9 SM3 assembly, D3D11 SM4 bytecode) | certain / medium | rewrite in order of material use; many are Unity built-ins, whose source Unity publishes per version (5.2.2f1); one test scene per shader | shaders done vs used |
| R5 | **Animation decoding**: Mecanim muscle clips (streamed, dense, constant) and avatars are intricate | medium / medium | AssetStudio's decoder (open source) as reference; the FBX references in `DoK-Assets\Models` to compare poses; sample at the original's rate when exact curves are out of reach | pose error per clip |
| R6 | **Particle parity**: 18,748 Shuriken systems with Blackbird's FX layer on top | high / low–medium | the module-usage report scopes the runtime; comparisons by eye; FX never affect the simulation | modules unsupported |
| R7 | **Middleware semantics without source**: Fabric, NGUI, CinemaDirector, PlayMaker, uScript | medium / medium | decompile them as specification (Plan 0.5); rebuild only what the content uses (usage reports, Plan 2.4) | |
| R8 | **Scope**: ~117k lines of simulation, ~180k of presentation, the mission logic, the content tools | certain / high | milestones that each produce something runnable; usage-driven scope (no general Unity reimplementation); the simulation verified headless before any presentation depends on it | milestone dates |
| R9 | **Corpus gaps**: code paths no recorded game exercises | medium / medium | coverage of the C++ simulation under the corpus; record games until the uncovered list is empty or explained | uncovered functions |
| R10 | **The asset path depends on AssetStudioModCLI** (stage 2a) | low / medium | its outputs are kept in `DoK-Assets`; stage 2b (our own reader) removes the dependency (D3) | |
| R11 | **Platform SDKs**: Steamworks and GOG Galaxy versions, availability and terms | low / low | isolated behind `Net` and a platform-services interface; LAN first | |
| R12 | **Legal**: the rebuild is a derivative work | certain / owner's call | private study; no original code or data in the repository or CI; the game cooks the owner's own installation and ships nothing of the original | any plan to publish |
