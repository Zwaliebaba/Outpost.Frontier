The smallest screen in 07, and three other documents now depend on it. 03 §9.7 makes UI scale 0.8–1.6× and three colour-vision palettes user-facing; 07b's whole palette contract assumes a player can pick one; and 07g's wheel rotation was just decided to take handedness from a settings toggle only, never inference. Gap-audit G15 caught that none of it had a home.

One rule shapes the whole screen: every control here is either an accessibility requirement or a decision the design deliberately refused to make for the player. Nothing is here because it was easier to add a setting than to choose. A settings screen is where design debt goes to hide, and this one is deliberately short.

The live preview is the whole design. Every setting on this screen is visual, and a player choosing a colour-vision palette from a dropdown labelled "Deuteranopia" is being asked to trust a word rather than judge a result. The preview shows real hull glyphs with real flag rings and real standings hues, so the choice is made by looking. The contrast audit runs beside it because 03 §9.7's 4.5:1 floor is a promise the screen should be able to prove, not just claim.

Three things were deliberately kept out. There is no graphics-quality menu — 03 §7 makes every enhancement a GpuCaps decision and 05 §3 degrades under pressure automatically, so a quality slider would be a second, worse scheduler fighting the first. There is no gesture rebinding: 03 §8 collapsed three binding sets into one grammar, and rebinding would reintroduce the mode-switch state machine rev A3 deleted. And there is no colour picker — the three palettes are audited against a contrast floor, and a free picker is a promise the audit cannot keep.

§3 DEPENDENCIES AND WHAT IS STILL OPEN
WHAT DEPENDS ON THIS SCREEN
▸ 07g §3.1 — the command wheel. Handedness is a settings toggle only, so the wheel cannot ship correctly without this screen. A hard prerequisite, not a nicety.
▸ 07b §4 — the palette contract. Three colour-vision palettes are the reason flag rings encode state by geometry as well as hue; if a player cannot select one, the contract is theoretical.
▸ 03 §9.7 — UI scale 0.8–1.6×. Re-layout, never bitmap scaling, so every screen's layout must already be scale-independent. This screen is where that claim gets exercised.
▸ 03 §11 — audio submixes. The duck matrix is data-driven, so category volumes are a natural setting rather than new machinery.
OPEN
▸ Where do settings live? Device-local, or on the account so a player's palette follows them to a second tablet? Account-side means a write path 06 has not designed, and 06 is still a placeholder.
▸ Is there a keybind surface at all? 03 §8 says mouse, keyboard, pad and touch drive one grammar — but it does not say whether the keyboard half is fixed or bound, and desktop players will expect to bind.
▸ Does the contrast audit ship? It is a strong accessibility statement and a small piece of runtime work nobody has costed. If it is a dev tool only, the screen loses its proof.
▸ F11 (debug HUD) — if the debug HUD ships in release, its toggle belongs here and this screen gains a sixth section.
