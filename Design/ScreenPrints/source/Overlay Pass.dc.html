SCALING LAW · {{ lawName }}

Pass placement and depth behaviour are one decision, not two. 03 §3's frame ends Tonemap → Ui → Present and the UI pass composites post-tonemap, so overlays in the Ui pass cannot depth-test against hulls, while overlays in their own pre-tonemap node get tonemapped and bloomed — a phosphor ring blown out by HDR is precisely the legibility failure 07b exists to prevent. Picking a slot picks an occlusion model.

§2 TWO MECHANISMS not a compromise — the two categories have different sources
A · PER-ENTITY, HIGH-COUNT
instanced off the culled InstanceRecord list
Selection rings · hull and shield bars · flag rings · lock and targeting markers · stale desaturation · velocity vectors
Zero new CPU work. InstanceRecord already carries selectionAndLodBias and teamColorAndFlags (03 §6), and GPU culling already compacts the visible set. The largest overlay class is a GPU-side expansion of a buffer that exists — it never touches the game thread.
Scales to the 1,024 cap for free.
B · CLIENT-AUTHORED, LOW-COUNT
projected geometry in UiDrawList
Order ghosts · waypoint polylines with per-leg ETAs · formation footprints · probe rings · aggregate extents · engagement arcs · off-screen indicators
These come from the client pre-check (02 §10) and presentation state (03 §10), not from replication, and their labels need the UI's layout and text machinery. A few hundred primitives worst case.
Bounded by orders in flight, not by entity count.

§4 SCALING LAW does a ring mean "this hull's size" or "this hull is selected"?
{{ law.tag }} {{ law.title }}
{{ law.sub }}
{{ s.label }}
{{ law.body }}

Recommended: screen-space minimum with a world-space ceiling — the ring tracks hull size while that reads above the floor, then stops shrinking. It keeps 07b's size channel meaningful where the eye can use it and guarantees a selected ship never becomes invisible, which is the failure that actually costs a fight. The cost is honest and worth stating: at the clamp the ring no longer reports tonnage, so a ring is a selection marker first and a size cue second.

§5 BUDGET, DETERMINISM, AND WHAT IS STILL OPEN
BUDGET — 00 §5.1
▸ Category A costs no game-thread time and no extract time: it consumes the compacted cull output, so it does not enter the 0.7 ms UI line or the 0.7 ms extract line at all.
▸ Category B is the only overlay work on the game thread, and it is bounded by orders in flight rather than entities. It shares the 0.7 ms UI budget and should declare a ceiling — recommend 0.15 ms, leaving 0.55 ms for the screens.
▸ GPU cost is one instanced draw per overlay class plus one UiDrawList batch. Needs a microbench in ns/overlay at the 1,024 cap, SKU-named per 00 §5.0.
DECIDED — 2026-08-08
✅ F7 — dedicated node, post-tonemap, depth as an SRV.
✅ De-clutter runs GPU-side on a stable sort key over replicated fields. Draw order is never an input; if the key is not total, chip membership flickers.
✅ Velocity vectors retire at Operational. Formation outlines already carry direction, and a merged vector would imply a cohesion the simulation may not model — a lie the renderer would be telling on the sim's behalf.
✅ Occlusion: plane-lying classes only — selection rings, formation footprints, probe rings. Screen-facing information never occludes; a hull must never hide the bar that reports it.
✅ Screen-space minimum with a world ceiling, and 0.15 ms for Category B.
⬜ Soft-occlusion depth bias still has no owner — too tight and rings z-fight the hulls they wrap, too loose and the ring floats off the plane.
