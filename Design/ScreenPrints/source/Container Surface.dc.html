FORWARD DESIGN, STATED: the container taxonomy (ItemTypeId, six kinds + Deploying) is upstream with no ADR here — the same standing gap D-P2 and D-P4 record. What this corpus does own: the wreck is fully ruled (ADR-024 §5b — half drops floored, finders-keepers, SCOOP as a context action, 900 s, non-durable), escrow is drawn on D-P4's order cards, and E3's own defect history supplies the third kind's reason to exist. The panel invents no kind; it gives the ruled ones their one shared surface.

The claim the whole surface rests on: cargo is never nowhere. Every unit of property sits in exactly one container at all times — a hold, a Bay, a wreck, an escrow, an assembly in motion — and E3 proved what happens when a transition forgets that (`ApplyTransit` spawned arrivals with empty holds; a fleet that warped lost its cargo silently). This panel is that invariant made visible: one component, instantiated by kind, showing the same (item, units, litres) stacks everywhere property can be.

§2 DESIGN CALLS
ONE COMPONENT, EVERY KIND
The panel is a single surface every container kind instantiates: an identity header (kind, claim rule, lifetime), the same (item, units, litres) stack list D-P2's vocabulary fixed with D-C1's glyphs, and at most one verb. Kinds differ by chrome — a wreck has a countdown, an escrow has an order reference, a Deploying container has an assembly timer — never by layout. When the taxonomy's remaining kinds land, each is a header and a verb, not a screen.
CARGO IS NEVER NOWHERE
Deploying exists as a visible kind because E3's accept found the invisible version: `ApplyTransit` spawning arrivals with empty holds, cargo lost with no surface to notice on. Property in motion is still property — the panel shows it read-only with the assembly's own timer, and it resolves itself.
ONE VERB PER KIND — SOME HAVE NONE
Wreck: SCOOP. Escrow: nothing here — release is CANCEL on the market tab, and a second cancel button would be a second home for one verb. Deploying: nothing — it resolves itself. A panel with a verb rack would invent interactions the kinds do not have.
THE COUNTDOWN IS THE CLAIM RULE
A wreck's header states both halves of §5b in one breath: finders-keepers (nobody owns a wreck, so there is no yours/theirs chrome to design) and the 900 s scatter in caution amber — the same amber that means "will stop being true on its own" everywhere else. Worlds forget: a teardown takes the wreck, and the panel never promises otherwise.
CAPACITY BEFORE THE VERB
SCOOP previews the fill against the selection's free litres by the same pure pre-check every transfer runs — an enabled SCOOP is a promise, and a selection that cannot lift the stacks says which stacks fit, in litres, before anything flies. Bounce parity, extended to salvage.
§3 DELIBERATELY ABSENT · OPEN
ABSENT BECAUSE THE DESIGN SAYS SO
▸ No loot splitting — finders-keepers means first scoop wins; a split UI would invent ownership where §5b ruled there is none.
▸ No jettison — player-made containers are a combat-era question; drawing the hook now would invent a mechanic (D-P2's own rule).
▸ No Bay here — the Bay is D-P2's whole screen; this panel covers what has no station under it.
▸ No wreck contents at range — you read a wreck by being on grid; remote wreck intel is the intel game's, not this panel's.
OPEN — RULINGS OWED
▸ The taxonomy ADR itself — the standing gap, third print to cite it. Until it lands here, the six-kind claim rests on an uncitable document.
▸ Wreck stack visibility — proposed public to everyone on grid (finders-keepers implies it); the alternative (scan-to-reveal) is future intel gameplay.
▸ Partial scoop order — when not everything fits: value density or stack order? The CARGO fill's ore-order question, third appearance; one ruling should close all three.
▸ Deploying visibility to others — the assembly is announced; whether its manifest is too (a scout reading what a forming fleet carries) is a real intel decision.
