PREVIEW · {{ stateLabel }}

This screen is the whole answer to "compose new fleets." ADR-017 made fleets and wings emergent — a fleet is whatever undocks together, a wing exists iff a ship carries its id — so the hangar is not a management screen over fleet objects; there are none. It is a selection surface: pick docked ships, pick a formation, UNDOCK. Everything else here exists to make that selection fast at 60 ships and honest about what happens next.

One rule shapes the layout: the roster keeps no damage state — a docked ship has no gauges, so there are no hull bars anywhere on this screen, and REPAIR is a stub reading FREE rather than a system. A chip is a class glyph, a name, a wing. That is the entire vocabulary, and it is why sixty ships fit without a scrollbar.

The parking diagram is on the screen because the ADR made a promise the player must be able to trust. Undock is never refused for clutter — the fleet self-parks at a scanned free bearing or holds at the point under protection. A player who cannot see the rings will read the parking flight as their ships wandering off. The diagram shows the undock point, both rings, and where the last fleet parked; it is a readout of the deterministic scan, not a control.

§2 DESIGN CALLS THE ADR LEAVES TO THE PRINT
TABS, NOT TILES — THE STATION GROWS SIDEWAYS
The station's future (repair pricing, refit, blueprint construction, market) arrives as sibling tabs in a fixed row, not panels inside the hangar — so the hangar's layout never reshuffles when a service lands, and each service gets a full screen's worth of room, which is the same argument that rejected the 260 px roster column. Built services take their place in the row as they land (CARGO — D-P2, REFINERY — D-P3); unbuilt tabs are visible and disabled with their reason (REPAIR — FREE, no priced work to show; REFIT / CONSTRUCT / MARKET — FUTURE), exactly as the strategic map stubs its unbuilt overlays. The undock composer belongs to the HANGAR tab alone: undocking is the hangar's verb, and a global composer would let a MARKET screen launch fleets.
WINGS ARE COLUMNS, SELECTION IS ADDITIVE
The roster groups by wing because the wing is the unit a player actually undocks. Tap toggles a ship; holding a wing header takes the whole wing; the composer accumulates across wings — so "Talon plus two spare Battleships from Reserve" is three gestures, not a drag across sixty chips. UNASSIGNED (wing 0) is a real column, not an afterthought: newly docked strays land there, and the ADR's "reorganisation room" is mostly the act of emptying it.
NEW WING NEVER SHOWS A NUMBER PICKER
A wing is a u8 the server never names; "new wing" is the client picking an unused id and asking for a name — the name goes to the user settings layer, the id goes on the wire. The player experience is "name a wing"; the protocol experience is `AssignWing(7)`. The id shows only as a small tag (· 3) beside the name, because two clients without shared settings will see numbers, and the print should admit that rather than hide it.
UNDOCK IS THE ONLY PRIMARY ACTION
68 px, always visible, disabled with a reason rather than hidden ("SELECT SHIPS TO UNDOCK"). The >64 case is declared before commit as waves, not refused after — `MAX_SHIPS_PER_ORDER` is a wire constant the player should never meet as an error. The pre-check runs against the same RosterView the server validates with, so a tappable UNDOCK is a promise: bounce parity, extended to station commands.
REMOTE IS A BADGE, NOT A MODE
Focus never gates command (ADR-016 §7), so this screen opens for any station holding your ships. The only differences remote: an amber badge in the status bar, and the undock confirmation says where the fleet will spawn ("undocks at Vesta-3 — view?"). Same layout, same verbs — a second layout for remote would be two screens to keep honest for one replicated roster.
§3 DELIBERATELY ABSENT · STILL OPEN
ABSENT BECAUSE THE ADR SAYS SO
▸ No hull/shield bars, no repair queue — the roster holds no gauges; REPAIR stubs as FREE and is the named hook for a priced version.
▸ No capacity meter — stations dock unlimited ships; a cap is a future scarcity design, and drawing a meter now would invent one.
▸ No DOCK verb here — docking is a context action on the station structure, out in the world. This screen is only ever entered docked or remote.
▸ No others' ships — docked is absolutely private; there is no "station traffic" panel to design.
OPEN — FOR THE PRINT REVIEW
▸ Wave 2 trigger. "When wave 1 clears the point" is this print's proposal; the ADR only caps the order at 64. Needs a rule — clears the point, or a flat delay?
▸ Does the composer persist? A half-built selection surviving a screen switch is convenient and a stale-selection hazard; proposal: it clears on undock, survives navigation within a session.
▸ Wing colour identity. Chips could tint by wing for scanning speed, but wing count is unbounded (1..255) and the palette is contract-bound. Proposal: no per-wing colour; position is identity.
▸ Sort inside a wing. Class-then-name shown here; the ADR is silent.
